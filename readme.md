# ScreenSwap

一个常驻后台的 Windows 双屏小工具：用一组全局快捷键，在两台显示器之间切换「主显示器」，并可同时把两屏上的桌面窗口整体互换。使用 C# / WPF 开发，界面为深色主题，关闭窗口后自动最小化到系统托盘继续工作。

## 主要功能

- **切换主显示器**：通过 Windows CCD API（`QueryDisplayConfig` / `SetDisplayConfig`）平移虚拟桌面坐标，让目标显示器成为新的 `(0, 0)` 原点。切换过程中保持两台显示器的物理左右 / 上下排列不变。
- **桌面窗口互换**：切换前后记录顶层窗口位置，把 A 屏的窗口按相对坐标移到 B 屏、B 屏的移到 A 屏；最大化窗口会先还原、移动、再重新最大化。该功能可在选项中关闭。
- **自定义全局热键**：提供三组可自由设置的快捷键，窗口隐藏、程序在后台时依然生效。
- **后台运行**：系统托盘图标 + 右键菜单（打开设置 / 立即切换 / 退出）、开机自启、启动即隐藏、气泡提醒、单实例保护。
- **严格的双屏校验**：检测到的显示器数量不等于 2 时，会弹出托盘警告并**拒绝执行切换**，界面上的「设为主显示器」按钮也会被禁用。

## 运行环境

- Windows 10 / 11（x64），两台显示器且处于「扩展这些显示器」模式（复制模式不可用）。
- [.NET 10 桌面运行时](https://dotnet.microsoft.com/download)（`Microsoft.WindowsDesktop.App` 10.x）。若使用自包含发布包则无需另装运行时。
- 无需管理员权限即可正常使用；若要移动任务管理器等以管理员身份运行的程序窗口，需以管理员权限启动本程序。可在「运行选项」中开启「以管理员权限开机自启动」，或点击「以管理员权限重新启动」在当前会话临时切换。

## 快速开始

直接运行编译输出或发布目录中的 `ScreenSwap.exe`：

```
bin\Release\net10.0-windows\ScreenSwap.exe
```

首次启动默认快捷键为 **`Ctrl + Alt + S`**：按一次切换到另一台显示器为主屏，再按一次切回。主显示器变化后，任务栏、桌面图标与新开窗口的默认位置会随之出现在新的主屏上。

托盘图标：双击打开设置窗口；右键可立即切换、开关「窗口互换 / 开机自启」或退出程序。点击窗口右上角的最小化 / 关闭按钮只会隐藏到托盘，不会退出。

## 快捷键设置

| 用途        | 默认值              | 说明                 |
| --------- | ---------------- | ------------------ |
| 切换主显示器    | `Ctrl + Alt + S` | 在当前主屏与另一台之间来回切换    |
| 显示器 1 设为主 | 未设置              | 直接指定某台为主屏，已是主屏时不操作 |
| 显示器 2 设为主 | 未设置              | 同上                 |

操作方式：点击输入框后**直接按下想要的组合键**即可；按 `Backspace` / `Delete` 或点「清除」可清空该快捷键。除 `F1`–`F12`、`PrintScreen` 外，组合键需至少包含一个修饰键（`Ctrl` / `Alt` / `Shift` / `Win`），以免占用普通按键。

注意事项：

- 「显示器 1 / 2」按虚拟桌面坐标从左到右（再从上到下）排序，与显卡接口编号或 Windows 设置里的数字编号可能不一致。
- 若组合键已被其它程序占用，或两组快捷键重复，`RegisterHotKey` 会失败，状态栏会给出提示，此时换一个组合键即可。部分 `Win` 组合由系统保留，无法注册。
- 设置会自动保存，也可点「保存并应用」重新注册热键。

## 运行选项

| 选项       | 默认 | 说明                                                                             |
| -------- | -- | ------------------------------------------------------------------------------ |
| 同时调换桌面窗口 | 开  | 关闭后只切换主显示器，不移动任何窗口                                                             |
| 开机自动启动   | 关  | 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，带 `--minimized` 参数后台启动 |
| 以管理员权限开机自启 | 关 | 依赖上一项；改用登录计划任务在后台以最高权限启动，首次勾选需确认一次 UAC |
| 启动时隐藏到托盘 | 关  | 启动时不显示设置窗口，热键仍可用                                                               |
| 托盘气泡提醒   | 开  | 切换结果、显示器数量不符、热键注册失败时提示                                                         |

管理员模式说明：注册表 `Run` 项由资源管理器以普通令牌拉起，无法获得管理员权限，因此开启「以管理员权限开机自启动」后，程序会创建一个名为 `ScreenSwap Admin AutoStart` 的登录计划任务（`LogonTrigger` + `HighestAvailable`），登录时静默取得当前用户的最高权限并带 `--minimized` 启动，之后不再弹出 UAC 提示。创建或删除该任务时需要一次 UAC 授权（Windows 的硬性要求）；取消勾选会删除任务并恢复为普通模式，两者始终互斥，不会开机启动两个实例。也可在「任务计划程序」中手动删除该任务。若当前会话想直接以管理员运行，点击设置窗口的「以管理员权限重新启动」即可，程序会自动退出旧实例。

配置文件：`%AppData%\ScreenSwap\settings.json`（JSON，修改后保存即生效；文件损坏时自动回退默认值）。

## 命令行参数

| 参数            | 作用                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| `--minimized` | 本次启动直接隐藏到系统托盘                                                                                         |
| `--diagnose`  | 只读诊断：不创建窗口、不注册热键、不改动显示配置，输出显示器列表、CCD 结构体尺寸、当前拓扑，并让系统校验一次切换配置。报告写到 `%TEMP%\ScreenSwap_diagnostics.txt` |
| `--restart` | 内部使用：以管理员权限重启时，让新实例在单实例互斥体冲突时短暂重试，等待旧实例退出 |
| `--admin-task <请求文件>` | 内部使用：提权辅助进程据此创建 / 删除管理员自启计划任务，执行后立即退出，不创建窗口 |

诊断模式适合排查「切换无效」：若报告提示结构尺寸不符或配置校验失败，通常是显卡驱动或显示模式的问题。

## 已知限制与注意事项

**不建议在游玩游戏时使用本软件。** 全屏 / 独占全屏游戏对显示拓扑变化非常敏感，切换主显示器可能导致游戏退出全屏、黑屏、闪退、掉帧或分辨率被重置；带反作弊或独占显示控制的程序也可能误判异常。

由于 Windows 自身的窗口管理与权限限制，以下情况可能出现应用无法切换、窗口不跟随移动或显示异常（黑屏、闪烁、位置错乱、短暂卡住）：

- **置顶窗口、全屏应用、无边框全屏程序**：这类窗口常自行锁定位置或绕过标准窗口移动消息，`MoveWindow` 可能不生效或被程序立刻改回。
- **任务管理器等系统 / 高权限进程**：以管理员权限运行的窗口，普通权限进程无法移动；桌面、任务栏、Shell 相关窗口按设计被跳过，不会参与调换。如需移动高权限窗口，请以管理员权限运行本程序（默认不开启管理员自启，可在「运行选项」中设置）。
- **被跳过的窗口**：不可见、最小化、被 DWM 隐藏（Cloaked，如部分 UWP）、工具窗口、无标题窗口、尺寸过小（小于 80×60）的窗口以及本程序自身窗口。
- **最大化窗口**：需要先还原再重新最大化，过程中会有短暂闪烁；部分应用会重新计算自己的位置。
- **软件冲突**：部分美化软件（如 TranslucentTB、FluentFlyout 等）在使用 ScreenSwap 切换主显示器后，可能会**报错并自动退出**。

其它限制：

- 仅在**恰好两台**显示器时工作；单屏、三屏及以上、复制模式都会拒绝切换。
- 混合 DPI 缩放、不同刷新率、旋转竖屏、部分显卡驱动或远程桌面 / 虚拟显示器环境下，切换可能失败或窗口位置出现偏差；失败时状态栏会显示 Win32 错误码。
- 切换瞬间桌面坐标系会整体平移，任务栏、桌面图标、部分窗口位置会有瞬时变化/错位，属于 Windows 的正常行为。
- 每次切换都会把显示配置写入系统数据库（`SDC_SAVE_TO_DATABASE`），与在「Windows 显示设置」里改主屏的效果相同。

## 项目结构

```
App.xaml / App.xaml.cs          启动、单实例、诊断模式、全局样式
MainWindow.xaml(.cs)           设置界面、托盘、显示器卡片
Controls/HotkeyBox.cs          快捷键捕获输入框
Models/                        设置模型、显示器信息
Native/WinApi.cs               Win32 常量与 P/Invoke 声明
Native/DisplayConfigApi.cs     CCD 主显示器切换内核
Services/                      显示器枚举、热键管理、窗口调换、配置、自启与管理员计划任务
app.manifest                   DPI 感知（PerMonitorV2）
```

## 构建

```bash
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained false
```

项目目标框架为 `net10.0-windows`，同时启用 `UseWPF` 与 `UseWindowsForms`（托盘图标）。两者同时启用会引入 `System.Windows.Forms` / `System.Drawing` 的全局 `using`，造成 `Application`、`TextBox`、`Brush` 等类型名歧义，项目已通过 csproj 中的 `<Using Remove="..." />` 处理，新增代码文件遇到歧义时显式写全名即可。
